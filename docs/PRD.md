# 乌萨奇桌宠产品需求文档

版本：v0.4 · 日期：2026-09-06 · 状态：v3 形象已获认可，第一阶段透明包已制作并安装，宿主最终试用待用户确认

本项目分两阶段交付：**第一阶段，让用户先用上 Codex 里的乌萨奇桌宠；第二阶段，再做不依赖 Codex 的完整桌宠程序。** 第一阶段有自己的完成标准，不需要等第二阶段完成才能使用。

当前已完成动作素材整理、参考项目研究、[三组形象重绘样稿](../art/redraw-round-01/index.html)和[九组透明 Codex 动画](../pets/usagi-codex/index.html)。宠物包已安装到 `C:\Users\Narita\.codex\pets\usagi\`；[切换与试用说明](codex-usagi-setup.md)列出操作和验证范围。格式、逐帧视觉、控制器逻辑和安装测试通过；实际选择、唤醒与宿主互动尚未验收，Live2D 程序尚未实现。

## 1. 产品目标与已确认需求

乌萨奇应像原作中的角色一样，有鲜明的表情、身体节奏和调皮性格。它既能安静陪伴，也能通过连贯的小动作带来惊喜。

用户已经确认：

- 先改造 Codex 桌宠，再制作独立程序。
- 画风以官方角色形象为目标，重视脸型、五官、耳朵、身体比例、颜色和线条的一致性。
- 形象依据用户认可的原始动图，两个参考桌宠项目用于研究实现方式；乌萨奇的尾巴是白色圆形毛球，侧面和背面必须保持这一特征。
- 嘴巴下方有独立短弧线；身体应短圆、饱满，不能画成长躯干或明显收腰的兔子。三组 v3 试绘已按反馈修订并获用户认可，作为后续制作的形象基准。
- 最终需要鼠标视线跟随、动态响应、点击互动，以及在底栏上奔跑嬉戏。
- 视线跟随由眼部与头部的细微摆动共同表达，不能仅检查眼睛是否移动。
- 完整版明确采用 Live2D；该决定属于第二阶段，第一阶段仍交付 Codex 支持的图集。
- 动作应平滑、连贯，包含预备、发力、接触、缓冲和恢复，不能只切换几张互不衔接的表情图。
- 动作不限于举例：奔跑摔倒、脸贴地弹起、背身拍屁屁、拿棒跑、挥棒、叉腰发“哈”、躺地滑动、其他形态等都要纳入完整产品。
- 允许为了透明背景、完整身体和可控视线重新绘制素材。
- 每次完成改动都要提交 Git；每个功能测试通过后再交付。

当前建议但尚未由用户确认：第二阶段先支持 Windows；鼠标响应默认以看向鼠标和轻微身体反应为主，偶尔追逐需单独开启。它们不会阻碍第一阶段。

## 3. 第一阶段的角色与动画设计

### 3.1 先确定一只稳定的乌萨奇

优先使用用户认可的参考：首轮 01、02、03、06、07、08、09。首轮 04、05、10 被排除的是对应素材，不代表取消叉腰、“哈”或视线跟随需求。

制作顺序是先出正面基础形象和侧面跑动样张，再制作完整动画。基础形象需满足：

- 长耳、脸型、短肢和身材比例与认可参考一致；不能画成另一只泛化的黄色兔子。
- 缩短躯干、弱化腰部收窄，保留原片中圆润饱满的身体；嘴巴下方的独立短弧线列为正面逐帧检查项。
- 保留原作五官表达，不为未来视线跟随擅自加入明显眼白或放大的瞳孔。
- 同一套轮廓线、配色和体积关系贯穿所有动作。
- 白色圆形毛球尾巴随身体方向和遮挡变化；不得变成黄色凸起、长尾或在无遮挡的背面消失。正面被身体遮住时无需强行露出。
- 角色、耳尖、手脚与动作范围完整，背景真正透明，没有字幕、水印、场景残片或伪透明棋盘格。
- 在 Codex 实际显示尺寸下依然可辨认；浅色、深色和复杂桌面背景上都没有明显白边或缺损。

用户已认可本轮三组 v3 的基础形象与比例，[认可记录及文件指纹](../art/redraw-round-01/approval.json)固定这一基准。已据此制作九组透明动画；原有认可不代表新增姿态已获用户认可，也不代表 Codex 宿主或 Live2D 运行功能已经通过验收。

### 3.2 九组动画的内容建议

下面的状态名称和格数来自当前 Codex 格式；乌萨奇的具体表演是本项目建议，制作时可在同一状态含义内调整。它们不代表用户已经认可了新的画稿。

| Codex 状态 | 有效格数 | 乌萨奇表演建议 | 设计重点 |
|---|---:|---|---|
| idle | 6 | 安静站立、呼吸、眨眼，耳朵轻微变化 | 平静、低干扰，可自然循环 |
| running-right | 8 | 向右小跑 | 交替步态清晰，体积和脚底基准稳定 |
| running-left | 8 | 向左小跑 | 方向正确；镜像时保持帧序和步态节奏 |
| waving | 4 | 抬手打招呼再放下 | 有起势和回落，短小清晰 |
| jumping | 5 | 下蹲、起跳、落下、缓冲 | 耳朵跟随重心，落地不突然复位 |
| failed | 8 | 一愣、垂耳或泄气，再恢复 | 表达受挫；不强塞完整跑摔动作链 |
| waiting | 6 | 期待地看过来、轻微歪头 | 表达等用户回应，区别于普通待机 |
| running | 6 | 认真思考或忙碌的小动作 | 这是任务执行状态，不是脚下跑步 |
| review | 6 | 专注查看、思考后轻微点头 | 表达审阅，与忙碌和等待有所区别 |

共 57 个有效姿态格，另有 15 个空格。正式导出为 1536 × 1872 的透明 PNG/WebP，8 列 × 9 行，每格 192 × 208；多余格保持完全透明。本机 `26.901.5280.0` 同时支持九行版本 1 与十一行版本 2；本阶段交付已约定的九行版本 1。当前宿主将待机基础时长乘以 6，其他动作重复三次再进入待机，预览页已据此提供播放模式。基础逐行时长见[研究附录](reference-projects.md#3-codex-第一阶段的格式依据)。[OpenAI 图集说明](https://github.com/openai/skills/blob/main/skills/.curated/hatch-pet/references/codex-pet-contract.md) · [OpenAI 状态说明](https://github.com/openai/skills/blob/main/skills/.curated/hatch-pet/references/animation-rows.md)

### 3.3 第一阶段如何实现“连贯”

固定 4–8 格的状态动画存在表达上限。第一阶段通过相邻姿态的衔接、清晰的动作弧线、稳定比例和合适的收尾来改善观感，按宿主真实时长制作；不通过复制同一张图凑格数，也不以调快播放冒充补出动作。

左右跑动、跳跃等必须有真正的姿态变化。循环动画检查首尾衔接；状态起止尽量回到兼容的重心和站姿。宿主如何切换行、在哪一帧中断不由素材包决定，出现无法靠画稿解决的跳变时应记录宿主限制，不能宣称已经提供完整过渡系统。

长篇跑摔、挥棒连招、躺地滑动等保留在第二阶段，用足够的动作长度表达，不挤进第一阶段的短状态槽。

第一阶段保留原始画稿、透明高分辨率帧、动作来源和色板，便于下一阶段延续形象。已有分层应保留；完整眼部绑定和身体骨骼工程不作为第一阶段交付前置条件。

## 5. 第二阶段的核心体验

第二阶段先以 Windows 独立程序为建议目标；系统版本、多屏范围和性能预算在启动这一阶段时固定。以下为完整产品需求，首个原型可以分批验证，但不能把原型等同于全部完成。

### 5.1 鼠标视线与动态响应

视线跟随是“乌萨奇看向鼠标”，由眼部方向与头部轻微转动、点头或侧倾共同表达；耳朵可有延迟响应。身体姿态响应及靠近、追逐是另外的控制项。验收同时检查头部与眼部，不能仅以瞳孔移动或整张图倾斜判断完成。

稳定正面或侧面姿态允许眼部与头部小幅联动，保持原作五官风格，并设置自然的转动范围。鼠标快速移动时平滑响应；离开活动屏幕后缓慢恢复自然视线。转背时通过转头或转身表达注意力；闭眼、睡眠、脸触地和快速翻滚时暂停视线叠加，恢复稳定姿态后平滑接回。

建议默认不持续追鼠标，以免妨碍工作；可提供“只看鼠标”和“偶尔追逐”选项，具体默认行为待第二阶段确认。

### 5.2 点击、拖拽与安静陪伴

点击耳朵、脸或身体得到有区别的反应。点击与拖拽分开识别；拖动时暂停自主跑动，松手后落到有效地面，缓冲后恢复活动。互动中的点击遵循动作中断规则，不能瞬间跳到另一张无关姿态。

透明区域允许点击桌面和其他应用；角色实体的命中范围随当前姿态、朝向和缩放变化。提供暂停活动、声音开关、音量、大小、恢复位置与退出入口，并保存设置。关闭视线跟随不影响点击穿透。

### 5.3 任务栏上的活动

角色以脚底、脸部或躯干的实际接触点贴着地面活动，不以图片矩形底边代替接地点。底部任务栏可见时以其上沿作为地面；自动隐藏时建议以工作区底边作为安全落点。侧置任务栏、屏幕切换和缩放变化时重新确定可用区域，避免挡住任务栏操作或掉出屏幕。

奔跑的身体位移、脚步和音效使用同一时间基准。到达边缘时先减速或转身；拖放、摔倒与起身后回到合理位置，不能在空中继续水平行走。

除用户明确点名的需求外，表中新增素材只是候选。每组动作须完成入口、主体、出口，注明循环段、接触点、可中断点和允许叠加的眼头控制。道具握持与身体一起运动，不能漂浮或穿过身体。

### 5.5 连续动画和行为衔接

完整版明确采用 Live2D Cubism 的模型与动作系统。通过可控图层和参数表达眼、头、耳、身体、尾巴及道具的变化；头部小幅转动与身体摆动分别控制。复杂的摔倒、翻滚、转背、拍屁屁和挥棒要补绘必要角度和关键形态，再制作相应模型变形与动作连接。不能把缺失的背面直接拉伸出来。

第二阶段交付包含分层画稿、可编辑模型工程和动作工程，以及供程序加载的模型、纹理和动作文件；例如 Cubism 的 `.cmo3` / `.can3` 工程与 `.moc3`、`.model3.json`、`.motion3.json` 等运行数据。具体 SDK 平台在第二阶段确定。官方说明区分了编辑工程和运行导出，并支持在模型更新前处理动作、视线与物理参数。[运行数据导出](https://docs.live2d.com/en/cubism-editor-manual/export-moc3-motion3-files/) · [模型参数更新流程](https://docs.live2d.com/en/cubism-sdk-manual/use-framework-web/)

本轮三组 PNG 是已获认可的白底形象与姿态基准，尚未拆层、绑定或导出 Live2D 模型。第一阶段继续按 Codex 的固定格式导出，第二阶段的实时连续运动以 Live2D 模型验收。

渲染刷新率与画稿数量分开验收。逐帧动画可以连贯，但必须有合理中间姿态和节奏；提高播放速度、重复帧或移动整张静态图不能替代完整跑步。手绘风格允许有意的停顿和夸张形变，不要求每秒都产生 60 张不同画稿。

动作切换需要明确优先级。建议拖拽优先；点击反应在安全中断点接入；摔倒接触到回弹、挥棒发力等短段先完成，再响应后续动作；自主活动优先级最低。状态结束后通过停步、回身或恢复姿态接续。

### 5.6 音效

“哈”等声音使用真实音频文件，在对应动作事件点触发，支持静音和音量调节。设置重复间隔，避免连续点击叠加尖叫；取消动作后正确停止或收尾。现有 97 份 GIF/WebP 均不含音频，声音素材另行收集和确认。

## 7. 第二阶段的验收场景

以下场景在第二阶段启动时确认的目标系统和显示器范围内实际运行，不只观看素材预览；当前建议 Windows 优先：

1. 鼠标绕角色移动，视线和头身自然响应；快速划过不抖动、不破坏五官；背身、闭眼和触地时遵循例外规则。
2. 跑动 → 被点击 → 在合适时机停步或转头 → 互动 → 恢复活动，位置与动作连续。
3. 奔跑 → 摔倒 → 脸触地压缩 → 回弹 → 起身或继续跑；无穿地、瞬移和身体尺寸跳变。
4. 躺地滑行、背身拍屁屁、持棒跑和挥棒都能完整播放并自然接回其他动作。
5. 叉腰“哈”的动作与音效同步；静音有效；重复点击不会无限叠加声音。
6. 至少一种已选形态完整变入、活动、变回；期间比例、接地点和点击范围正确。
7. 拖拽释放、任务栏自动隐藏、改变显示缩放或切换约定支持的显示器后，角色仍在可操作区域并正确接地。
8. 透明区穿透、实体点击正确；关闭跟随后穿透仍有效；设置重启后保留，退出后无残留窗口。
9. 程序真实加载 Live2D 模型；可编辑工程、分层画稿和运行文件齐全。独立调节头部与眼部参数时无破面、接缝或错误遮挡；白色圆毛球尾巴在侧面、背面及动作切换中形状和颜色一致。

建议先以 60Hz 屏幕稳定渲染为体验目标，并分别记录待机、奔跑和复杂动作的卡顿、CPU、内存与连续运行稳定性。具体机器、测量时长和性能阈值在第二阶段技术样机验证后写入验收表，不能以尚未测量的数字宣称达标。
