# 乌萨奇桌宠产品需求文档

版本：v0.1 · 日期：2026-09-06 · 状态：可评审的需求稿

本项目分两阶段交付：**第一阶段，让用户先用上 Codex 里的乌萨奇桌宠；第二阶段，再做不依赖 Codex 的完整桌宠程序。** 第一阶段有自己的完成标准，不需要等第二阶段完成才能使用。

当前已完成动作素材整理和参考项目研究；本文定义后续交付，不表示宠物已经制作、安装或通过运行测试。

## 1. 产品目标与已确认需求

乌萨奇应像原作中的角色一样，有鲜明的表情、身体节奏和调皮性格。它既能安静陪伴，也能通过连贯的小动作带来惊喜。

用户已经确认：

- 先改造 Codex 桌宠，再制作独立程序。
- 画风以官方角色形象为目标，重视脸型、五官、耳朵、身体比例、颜色和线条的一致性。
- 最终需要鼠标视线跟随、动态响应、点击互动，以及在底栏上奔跑嬉戏。
- 动作应平滑、连贯，包含预备、发力、接触、缓冲和恢复，不能只切换几张互不衔接的表情图。
- 动作不限于举例：奔跑摔倒、脸贴地弹起、背身拍屁屁、拿棒跑、挥棒、叉腰发“哈”、躺地滑动、其他形态等都要纳入完整产品。
- 允许为了透明背景、完整身体和可控视线重新绘制素材。
- 每次完成改动都要提交 Git；每个功能测试通过后再交付。

当前建议但尚未由用户确认：第二阶段先支持 Windows；鼠标响应默认以看向鼠标和轻微身体反应为主，偶尔追逐需单独开启。它们不会阻碍第一阶段。

## 2. 两阶段范围

| 项目 | 第一阶段：Codex 乌萨奇 | 第二阶段：独立乌萨奇桌宠 |
|---|---|---|
| 使用方式 | 在现有 Codex 中选择乌萨奇宠物 | 独立启动、退出和设置，无需运行 Codex |
| 交付核心 | 透明角色动画包、预览、安装与恢复说明 | 可运行程序、正式动作素材、交互和行为系统 |
| 动画范围 | 适配 Codex 固定的 9 组状态 | 按动作需要设置时长、过渡、循环和中断点 |
| 鼠标与点击 | 沿用当前 Codex 宿主已提供的交互 | 独立视线、头身响应、点击分区、拖拽、可选追逐 |
| 底栏活动 | 沿用 Codex 的移动方式 | 任务栏接地、奔跑、滑行、摔倒和起身 |
| 声音和形态 | 不新增声音系统和形态调度 | 动作同步短音效、安静模式、连续形态变化 |
| 完成依据 | 画风认可、图集检查通过、Codex 实际可用 | 全部约定功能和完整场景测试通过 |

第一阶段通过 Codex 自定义宠物入口实现。当前公开的素材包格式只声明宠物信息和图集，没有自定义鼠标逻辑、音效或动作状态机字段。因此第一阶段不把这些能力作为素材包能新增的功能；具体点击、拖拽、状态触发效果仍需在用户当前 Codex 版本验证。[格式依据](reference-projects.md#3-codex-第一阶段的格式依据)

## 3. 第一阶段的角色与动画设计

### 3.1 先确定一只稳定的乌萨奇

优先使用用户认可的参考：首轮 01、02、03、06、07、08、09。首轮 04、05、10 被排除的是对应素材，不代表取消叉腰、“哈”或视线跟随需求。

制作顺序是先出正面基础形象和侧面跑动样张，再制作完整动画。基础形象需满足：

- 长耳、脸型、短肢和身材比例与认可参考一致；不能画成另一只泛化的黄色兔子。
- 保留原作五官表达，不为未来视线跟随擅自加入明显眼白或放大的瞳孔。
- 同一套轮廓线、配色和体积关系贯穿所有动作。
- 角色、耳尖、手脚与动作范围完整，背景真正透明，没有字幕、水印、场景残片或伪透明棋盘格。
- 在 Codex 实际显示尺寸下依然可辨认；浅色、深色和复杂桌面背景上都没有明显白边或缺损。

用户认可基础形象后再展开整套图集。这是画风验收节点，不要求此时决定第二阶段的技术方案。

### 3.2 九组动画的内容建议

下面的状态名称和格数来自当前 Codex 格式；乌萨奇的具体表演是本项目建议，制作时可在同一状态含义内调整。它们不代表用户已经认可了新的画稿。

| Codex 状态 | 有效格数 | 乌萨奇表演建议 | 设计重点 |
|---|---:|---|---|
| idle | 6 | 安静站立、呼吸、眨眼，耳朵轻微变化 | 平静、低干扰，可自然循环 |
| running-right | 8 | 向右小跑 | 交替步态清晰，体积和脚底基准稳定 |
| running-left | 8 | 向左小跑 | 方向正确；镜像时保持帧序和步态节奏 |
| waving | 4 | 抬手打招呼再放下 | 有起势和回落，短小清晰 |
| jumping | 5 | 下蹲、起跳、落下、缓冲 | 耳朵跟随重心，落地不突然复位 |
| failed | 8 | 一愣、垂耳或泄气，再恢复 | 表达受挫；不强塞完整跑摔动作链 |
| waiting | 6 | 期待地看过来、轻微歪头 | 表达等用户回应，区别于普通待机 |
| running | 6 | 认真思考或忙碌的小动作 | 这是任务执行状态，不是脚下跑步 |
| review | 6 | 专注查看、思考后轻微点头 | 表达审阅，与忙碌和等待有所区别 |

共 57 个有效姿态格，另有 15 个空格。正式导出为 1536 × 1872 的透明 PNG/WebP，8 列 × 9 行，每格 192 × 208；多余格保持完全透明。格式与逐行时长见[研究附录](reference-projects.md#3-codex-第一阶段的格式依据)。[OpenAI 图集说明](https://github.com/openai/skills/blob/main/skills/.curated/hatch-pet/references/codex-pet-contract.md) · [OpenAI 状态说明](https://github.com/openai/skills/blob/main/skills/.curated/hatch-pet/references/animation-rows.md)

### 3.3 第一阶段如何实现“连贯”

固定 4–8 格的状态动画存在表达上限。第一阶段通过相邻姿态的衔接、清晰的动作弧线、稳定比例和合适的收尾来改善观感，按宿主真实时长制作；不通过复制同一张图凑格数，也不以调快播放冒充补出动作。

左右跑动、跳跃等必须有真正的姿态变化。循环动画检查首尾衔接；状态起止尽量回到兼容的重心和站姿。宿主如何切换行、在哪一帧中断不由素材包决定，出现无法靠画稿解决的跳变时应记录宿主限制，不能宣称已经提供完整过渡系统。

长篇跑摔、挥棒连招、躺地滑动等保留在第二阶段，用足够的动作长度表达，不挤进第一阶段的短状态槽。

## 4. 第一阶段的步骤、交付与验收

| 步骤 | 产出 | 进入下一步的条件 |
|---|---|---|
| A：形象定稿 | 正面基础形象、侧面样张、配色与比例记录 | 用户认可角色外观 |
| B：动画样片 | 待机与左右跑动，按 Codex 时长预览 | 比例、步态、透明边缘和循环检查通过 |
| C：完整图集 | 9 组动画、图集、pet.json、逐组预览 | 文件和视觉检查全部通过 |
| D：Codex 试用 | 本机可选择的宠物包、实际试用记录、恢复说明 | 当前 Codex 加载和交互测试通过 |

交付目录建议为 `pets/usagi-codex/`，其中 `pet.json` 与 `spritesheet.webp` 是加载包；预览和源文件另存，避免把研究原片当成运行素材。安装时使用独立的宠物目录，不覆盖 Codex 内置文件；如同名目录已有内容，先保留旧版本。提供切回原宠物和移除本包的说明。

必须完成的检查：

| 检查 | 通过标准 |
|---|---|
| 文件与布局 | 清单可解析、图片路径存在；尺寸、9 行有效格数、空格透明完全符合格式 |
| 透明与完整性 | 所有有效格都有完整角色；无邻格残片、边缘裁切、背景块，透明像素无导出残留 |
| 动画预览 | 每组按规定时长连续播放至少 3 次；无非设计造成的变大变小、基准漂移、错向或首尾跳变；待机首帧单独显示时也完整自然 |
| 状态含义 | 9 组状态可区分，idle 安静，running 明确表示任务忙碌；不是反复复用同一套跑步 |
| 外观 | 原尺寸和实际宠物尺寸检查通过，并在浅、深及复杂背景检查；用户认可最终画风 |
| 本机可用 | 当前 Codex 识别并显示乌萨奇；可切换和恢复；正常使用中不出现空白格或缺图 |
| 宿主交互 | 可触发的点击、拖拽和任务状态必须实测并记录结果；经核实当前宿主不提供触发入口的状态，以逐行预览验收并列为已知宿主限制 |

本机验收记录需注明 Codex 版本、系统和显示缩放。素材通过检查不等于宿主测试通过；本应可触发但尚未测试的项目仍为未完成，不能将第一阶段标成全部验收完成。已核实的宿主入口限制不阻碍素材包交付，但不能将对应状态写成已通过宿主实测。

第一阶段保留原始画稿、透明高分辨率帧、动作来源和色板，便于下一阶段延续形象。已有分层应保留；完整眼部绑定和身体骨骼工程不作为第一阶段交付前置条件。

## 5. 第二阶段的核心体验

第二阶段先以 Windows 独立程序为建议目标；系统版本、多屏范围和性能预算在启动这一阶段时固定。以下为完整产品需求，首个原型可以分批验证，但不能把原型等同于全部完成。

### 5.1 鼠标视线与动态响应

视线跟随是“乌萨奇看向鼠标”；身体跟随是“它转头、倾身、靠近或追逐”。二者分别控制，不能只让整张图倾斜便视为眼神跟随完成。

稳定正面或侧面姿态允许眼部与头部小幅联动，保持原作五官风格，并设置自然的转动范围。鼠标快速移动时平滑响应；离开活动屏幕后缓慢恢复自然视线。转背时通过转头或转身表达注意力；闭眼、睡眠、脸触地和快速翻滚时暂停视线叠加，恢复稳定姿态后平滑接回。

建议默认不持续追鼠标，以免妨碍工作；可提供“只看鼠标”和“偶尔追逐”选项，具体默认行为待第二阶段确认。

### 5.2 点击、拖拽与安静陪伴

点击耳朵、脸或身体得到有区别的反应。点击与拖拽分开识别；拖动时暂停自主跑动，松手后落到有效地面，缓冲后恢复活动。互动中的点击遵循动作中断规则，不能瞬间跳到另一张无关姿态。

透明区域允许点击桌面和其他应用；角色实体的命中范围随当前姿态、朝向和缩放变化。提供暂停活动、声音开关、音量、大小、恢复位置与退出入口，并保存设置。关闭视线跟随不影响点击穿透。

### 5.3 任务栏上的活动

角色以脚底、脸部或躯干的实际接触点贴着地面活动，不以图片矩形底边代替接地点。底部任务栏可见时以其上沿作为地面；自动隐藏时建议以工作区底边作为安全落点。侧置任务栏、屏幕切换和缩放变化时重新确定可用区域，避免挡住任务栏操作或掉出屏幕。

奔跑的身体位移、脚步和音效使用同一时间基准。到达边缘时先减速或转身；拖放、摔倒与起身后回到合理位置，不能在空中继续水平行走。

### 5.4 丰富的动作与形态

必须覆盖用户明确提出的动作，并从现有参考中逐步扩充；素材数量不是正式动作数量承诺。

| 动作需求 | 当前对应参考 | 制作要求或缺口 |
|---|---|---|
| 奔跑中摔倒、脸触地弹起后恢复 | [U001 跑摔弹起](../references/action-library/actions/run-bounce/README.md) | 完整串起跑动、失衡、触地、形变、回弹与继续活动 |
| 躺在地上滑动 | [U002 贴地挪动](../references/action-library/actions/ground-scoot/README.md)、[U021 仰躺翻滚](../references/action-library/actions/lying-wiggle/README.md) | 现有参考不是干净稳定的侧向滑行；需补清晰参考或重绘验证 |
| 背身拍屁屁 | [U003 背身拍屁屁](../references/action-library/actions/butt-pat/README.md) | 包含转背、拍打、身体反作用和回身 |
| 挥动黄色长棒 | [U004 挥棒](../references/action-library/actions/staff-fireworks/README.md)、[U005 挥棒后摆架势](../references/action-library/actions/staff-stance/README.md) | 保留持握、棒的运动弧线和收势 |
| 拿着黄色长棒跑步 | 暂未找到确切连续参考 | 不能把挥棒、抱刷子跑当成同一动作已找到；需补参考或以已认可的棒与跑姿制作样片 |
| 叉腰并发“哈” | 准确姿态和音频均待补充 | 动作与实际声音同步；文字气泡不算完成声音需求 |
| 奔跑、转身、旋转、嬉戏 | [U006 迎面跑](../references/action-library/actions/run-approach/README.md)、[U007 转身跑远](../references/action-library/actions/turn-run-away/README.md)、[U008 转圈](../references/action-library/actions/spin-in-place/README.md) | 转成适合桌面空间的完整动作，补齐起止姿态 |
| 休息、进食及其他日常小动作 | [U047 平躺睡眠](../references/action-library/actions/sleep-on-back/README.md)、[U056 交替进食](../references/action-library/actions/alternating-bites/README.md) 等 | 作为自主活动变化，控制频率和干扰 |
| 不同服装或形态 | [U074 香蕉装](../references/action-library/actions/banana-run/README.md)、[U083 跳出睡衣](../references/action-library/actions/jump-out-pajamas/README.md)、[U087 星星形态](../references/action-library/actions/star-jump-fall/README.md) 等 | 首批具体形态待挑选；切换需有穿脱、转身或变形过程，不能直接换图 |

除用户明确点名的需求外，表中新增素材只是候选。每组动作须完成入口、主体、出口，注明循环段、接触点、可中断点和允许叠加的眼头控制。道具握持与身体一起运动，不能漂浮或穿过身体。

### 5.5 连续动画和行为衔接

采用能保留原作轮廓的制作方式：细微呼吸、耳朵和视线可以分层控制；摔倒、翻滚、转背、拍屁屁和挥棒等复杂姿态需要充分绘制。最终是否采用骨骼、逐帧或混合方案，由小样效果决定。

渲染刷新率与画稿数量分开验收。逐帧动画可以连贯，但必须有合理中间姿态和节奏；提高播放速度、重复帧或移动整张静态图不能替代完整跑步。手绘风格允许有意的停顿和夸张形变，不要求每秒都产生 60 张不同画稿。

动作切换需要明确优先级。建议拖拽优先；点击反应在安全中断点接入；摔倒接触到回弹、挥棒发力等短段先完成，再响应后续动作；自主活动优先级最低。状态结束后通过停步、回身或恢复姿态接续。

### 5.6 音效

“哈”等声音使用真实音频文件，在对应动作事件点触发，支持静音和音量调节。设置重复间隔，避免连续点击叠加尖叫；取消动作后正确停止或收尾。现有 97 份 GIF/WebP 均不含音频，声音素材另行收集和确认。

## 6. 素材生产与两个阶段的复用

当前参考库包含 **91 组动作、97 份原始动图、10 个分类**，每组已有独立文件夹、来源、尺寸、帧数、审核状态及重绘说明。[浏览素材](../references/action-library/index.html) · [目录](../references/action-library/README.md) · [收集范围和缺口](../references/action-library/collection-report.json)

七组首轮认可素材已经保留；新增素材仍待用户挑选。外部合集的原作集数并未逐一确认，不能将整库称作已核实的官方素材。原始文件和出处保留用于动作追溯，正式作品使用经过验收的透明角色资源。

制作流程：选参考 → 标出关键姿态与节奏 → 补全身体并去除场景 → 统一画风 → 绘制中间姿态或可控图层 → 设置锚点与动作连接 → 导出 → 文件检查、视觉检查和实际运行检查。

第一阶段导出 Codex 固定图集；第二阶段从保存的源画稿和角色规范继续制作，不从低分辨率图集反推高质量眼部图层。眼、头、耳、身体、四肢和道具按实际可控需求拆分，避免只有压平文件。记录每个成品的参考来源、制作版本、透明范围、锚点、时长及测试结果。

## 7. 第二阶段的验收场景

以下场景在第二阶段启动时确认的目标系统和显示器范围内实际运行，不只观看素材预览；当前建议 Windows 优先：

1. 鼠标绕角色移动，视线和头身自然响应；快速划过不抖动、不破坏五官；背身、闭眼和触地时遵循例外规则。
2. 跑动 → 被点击 → 在合适时机停步或转头 → 互动 → 恢复活动，位置与动作连续。
3. 奔跑 → 摔倒 → 脸触地压缩 → 回弹 → 起身或继续跑；无穿地、瞬移和身体尺寸跳变。
4. 躺地滑行、背身拍屁屁、持棒跑和挥棒都能完整播放并自然接回其他动作。
5. 叉腰“哈”的动作与音效同步；静音有效；重复点击不会无限叠加声音。
6. 至少一种已选形态完整变入、活动、变回；期间比例、接地点和点击范围正确。
7. 拖拽释放、任务栏自动隐藏、改变显示缩放或切换约定支持的显示器后，角色仍在可操作区域并正确接地。
8. 透明区穿透、实体点击正确；关闭跟随后穿透仍有效；设置重启后保留，退出后无残留窗口。

建议先以 60Hz 屏幕稳定渲染为体验目标，并分别记录待机、奔跑和复杂动作的卡顿、CPU、内存与连续运行稳定性。具体机器、测量时长和性能阈值在第二阶段技术样机验证后写入验收表，不能以尚未测量的数字宣称达标。
